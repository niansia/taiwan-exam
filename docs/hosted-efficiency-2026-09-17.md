# 網頁出卷排版修正循環縮短

本次針對使用者回報的數 A 實測耗時修正排版、審閱沿用與上標排版。所有逐頁、逐題、難度與最終檢查閘門保留；變更的是重工與手動整理資料的方式。

## 使用者提供的計時

| 階段 | 時間 | 比例 |
|---|---:|---:|
| 排版與修正（render_repair） | 約 38 分 5 秒 | 58% |
| 完整命題（authoring） | 約 16 分 54 秒 | 26% |
| 難度複核（difficulty_qa） | 約 5 分 20 秒 | 8% |
| 重新解題（solving） | 約 3 分 22 秒 | 5% |
| 全程 | 約 65 分 41 秒 | 分三次對話完成 |

主要修正為第 3 題圖文配置造成的頁面空間，以及第 11 題 T² 上標可讀性。實際檢查 7 張題本頁、8 張詳解頁與 40 個逐題裁切，共 55 個單位；另有 3 個頁尾留白警示需用內嵌官方頁面數據比較。本次沒有取得該網頁工作階段的原始工具日誌，以下原因來自程式檢查與本機重現。

## 程式中確認的原因

1. **版面規格重打一次題目。** 沒有由 exam.json 產生正文規格的工具，模型需把 20 題題幹、選項與詳解再寫成兩份 blocks JSON；修改內容時也要同步改兩處。
2. **修一題會讓後面的審閱全部失效。** 舊的沿用條件要求整份 exam 雜湊不變，且逐題裁切的頁碼、位置與像素完全相同。任何內容修正或往後推移的排版都會讓之後的逐題審閱重來。此外固定模板頁面寬 594.96 pt，正文 595.28 pt，合成時會等比縮放；本機以七科版型在真實模板合成下量測，191 個移位但未改動的題塊只有 114 個像素完全相同。
3. **表格內的上標被壓回基線。** 選擇題、非選擇題題幹與選項都排在表格儲存格內。MuPDF 會把儲存格的 `vertical-align:top` 套用到儲存格內每段文字，使 `T<sup>2</sup>` 的 2 與基線相差僅約 0.09 pt，看起來像 T₂；同樣內容放在段落中則上移約 3.7 pt。這類問題只能在看圖時發現，並觸發重排與重審。
4. **留白警示需手動查資料。** 頁尾留白超過門檻時，要自行從 calibration.json 找同角色官方頁面、核對雜湊與數值，再寫入處置紀錄。
5. **審閱紀錄需手動編修 JSON。** 55 筆觀察需寫入不同報告，再另外更新雜湊；圖片一次開一張。

## 已實作

- `run_hosted_workflow.py specs`：依 exam.json 產生題本與詳解規格。文字只取自已存的題目、選項、作答位置、`answer_format`、`option_layout`、圖片與詳解；特殊結構（含空格的文章、選項庫、表格）寫在 hints。產生後被手改或早於目前 exam 的規格會被拒用。
- `run_hosted_workflow.py proof`：每批存檔後只排該批題目與詳解，使用正式排版器與固定頁面縮放，產生可審閱的逐題裁切。
- 逐題沿用規則：題目與詳解的紀錄未變（難度設計、審閱等不列印的欄位除外；共用題組一起綁定），字型與排版程式未變，且新裁切像素相同，或字形、字型、線條、圖片（含透明遮罩的解碼像素，依內容串流確認實際物件）與相對位置在 0.02 pt 內一致，才沿用先前實際審閱。舊審閱若在等價排版上記錄了非通過的發現，則不沿用。頁面審閱只在整頁像素、機械警示與該頁題目內容都未變時沿用；封面與公式頁需像素與區段文字未變。
- 正文排版：題塊起點與裁切邊界對齊 0.5 pt 格線；右側圖額外 0.025 pt 行高以避開像素格線邊界；文字儲存格改為基線對齊、圖片儲存格維持靠上，修正上標與下標位置。選項欄數支援 1–5。
- 組版結果列出 `review_queue` 與依頁分組的 `review_batches`；每個留白警示附 `density_evidence`，無任何同角色官方頁面可合理化時列入 `reflow_before_review`。
- `record-review`：把審閱者自己的觀察寫入報告、確認圖片未變並更新雜湊，列出剩餘項目；不提供預設通過或觀察文字。

最終檢查程式 `check_hosted_run.py` 未修改：兩本最終 PDF 的每頁都要有審閱紀錄，每個逐題裁切都由最終 PDF 重新產生並比對，固定模板、留白、答題格碰撞與難度閘門照舊。

## 其他科目的同類問題

數 A 的修正完成後，逐一檢查國綜、國寫、英文、數 B、社會、自然。依據為各科驗證程式、原本維護的正式版面渲染程式所使用的 exam.json 慣例，以及 115 官方卷的計分小題結構。以合成版面實際排出兩本題本／詳解並逐頁查看，發現下列同類問題並已修正：

| 科目 | 問題 | 修正 |
|---|---|---|
| 全科 | 版面規格只支援一般選擇、選填、非選題欄位，其他格式仍需手打 | `specs` 依原渲染程式慣例投影各科格式：選項標為 `(A)`／`(1)`、`______` 選填位置、共用圖只印一次、題組標示、跨頁材料分段 |
| 英文 | 綜合測驗、文意選填、篇章結構（11–34 題）只印在文章與選項庫中，最終檢查卻要求每題各有裁切 | 新增 `covers`：印在共用文章的題目由該區塊涵蓋；`[[n]]` 空格、`*斜體*`、選項庫只印一次、綜合測驗選項列與題號同一基線；英文題幹與選項使用英文字型 |
| 自然 | 多選題「應選 n 項」依規定由 `required_selection_count` 產生，版面投影原本不會加上 | 自動附加且只印一次；題幹手寫「應選」時直接指出題號；H₂O、SO₄²⁻ 等 Unicode 上下標改為正式上下標 |
| 社會 | 作答格式表（`response_format_table`）未投影；「勾選＋理由」子題的配分寫在題幹（整題合計）時會再印一次 | 表格與題目同頁保持；題幹已寫出整題或單題配分時不再追加 |
| 國綜、國寫 | 長篇材料與子題共用題號，範圍標示會印成「第 32 至 32 題為題組」；材料過長時整塊移到下一頁，留下大片空白（國綜、社會、國寫同角色官方頁面可接受的頁尾留白上限約 0.23、0.25、0.12） | 同題號子題不印範圍標示；長材料、題幹與詳解可在段落處接續到下一頁；`continuation_pages` 併入同一題的文字欄 |
| 數 A、數 B | 圖文題的題號沒有懸掛縮排、配分印在圖後；帶分隔符的 LaTeX 要到排版時才失敗 | 圖文題保留題號欄、配分放在圖前；`specs` 直接指出需改用已驗證公式素材的題號 |

Unicode 上下標：DFKai-SB、MingLiU、Microsoft JhengHei、Noto Sans/Serif TC 與 MuPDF 內建中文字型都缺 ₀–₉、₊₋ 與大部分 ⁴–⁹、⁺⁻。MuPDF 不會印出缺字方框，而是悄悄改用 Noto Serif，因此機械檢查抓不到，只會在 SO₄²⁻ 這類化學式出現粗細、大小不一的字形。

七科合成版面的本機檢查：每科題本與詳解都能由 `specs` 產生、排出，並完整涵蓋每一題；沒有印出未轉換的 `[[`、`{{`、`<sup>` 或 Unicode 上下標；長材料跨頁時，題號只在第一段、配分只在最後一段，非末頁頁尾留白低於 0.2。

## 預期影響與限制

以使用者這次的流程估算：題目文字不必重打；40 個逐題裁切改在各批命題時審一次，上標與圖文配置可在分頁前修好；最終組版主要檢查 15 頁；若仍需修正，只重審變動的題目與頁面；留白比較資料直接附在結果中。這是依流程推估，尚未以網頁實測驗證。

未納入本次修改：

- 內容審閱（answers、difficulty、originality、visuals 等）仍綁定整份 exam 雜湊，內容修正後仍需依現有規則重新綁定與複核。改成逐題綁定會變更最終檢查契約，宜另行評估。
- 未把多個裁切拼成一張圖。部分平台會縮小大圖，無法確保每題仍是可讀解析度；改為同一次呼叫開啟多張原尺寸圖片。
- 原生 Skill 工具 ZIP 尚未重新封裝與上傳驗證；知識檔已更新為 2026.09.17.1。
