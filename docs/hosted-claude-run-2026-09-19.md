# Claude 數 A 實跑：減少修正循環與檔案大小

使用者以 Claude 原生 Skill 出一份 116 學測數 A，成品版面完整、套用固定模板，但分三輪才完成：第一輪約 34 個指令、讀 14 個檔案；第二、三輪各讀約 20 個檔案，另跑 9 與 16 個指令。本文依對話摘要與交付的兩份 PDF，找出可在不減少檢查的前提下縮短的地方。沒有取得該執行環境的工具紀錄與計時檔。

## 觀察

| 現象 | 出現時機 | 原因 |
|---|---|---|
| 詳解殘留 LaTeX 指令、漏符號印出「$」、數學符號未配對、公式圖未註冊 | 排版後或最終逐頁審閱 | 存題時沒有檢查會印出的文字；`specs` 只擋 `\frac`、`\sqrt` 等少數寫法 |
| 題組流程圖超出欄寬 | 組版時報錯 | 圖寬超過有題號欄的文字寬度時只會報錯，要改寬度再重排 |
| 詳解末頁只剩兩行（留白 94.8%） | 第一次組版的留白警示 | 分頁固定題間距；只差一兩行也整段換頁 |
| 開第一張頁面圖路徑錯誤、需自行整理待審清單 | 最終審閱 | 待審圖片為相對路徑，紀錄格式要自己對照題號與頁碼 |
| 兩份 PDF 各約 40 MB | 交付 | 整套 Noto Serif CJK（約 20 MB）嵌入兩次：正文一份、頁首欄位一份 |

「第 14 題漏掉 log」是內容錯誤，只能靠審閱發現；「大題標題順序顛倒」無法從摘要重現，現有程式依題目順序輸出標題，未修改。

## 修正

- **存題時檢查印刷文字。** `append_items.py` 會拒收整批，並一次列出所有問題：LaTeX 指令、當作數學符號的「$」（金額如 `US$30,000` 可用）、未配對的 `<sup>`／`<sub>`／`<i>`／`<b>`、未在 `inline_assets` 宣告的 `{{asset:…}}`、找不到或雜湊不符的圖檔。`specs` 套用相同規則。
- **圖自動縮到欄寬。** 有題號欄的題目與詳解，圖寬上限為文字欄寬；超過時以欄寬印出，並記在版面紀錄的 `scaled_assets`。右側並排圖仍維持原本 180 pt 的限制與錯誤訊息。
- **末頁只剩一兩行時先收攏。** 最後一頁內容不到版面高度 20% 時，排版器改用 0.75 或 0.5 倍的題間距重排，頁數減少才採用，並記錄 `gap_scale`。字級、行距、圖都不變。
- **審閱清單可直接使用。** proof 與 build 回傳絕對路徑的圖片、每張圖對應的 `record_as` 鍵值，以及只含待審項目的 `observations_template`（狀態一律為 pending）；填好後一次 `record-review`。
- **PDF 瘦身。** 組版時合併重複的字型（幾乎不花時間，40 MB 變 20 MB）。`finalize` 最終檢查通過後，另存交付版：以 fontTools 只保留頁面實際畫出的字形，以 CID 為索引的 CFF 字型保留 CID、其他字型保留字形編號，頁面內容串流不改寫；逐頁以兩倍解析度比對畫面與文字，任何差異即保留完整字型。精簡每份需數秒，所以只在交付時做一次，不拖慢每次組版。沒有 fontTools 時只合併重複字型。

## 本機量測

| 項目 | 結果 |
|---|---|
| 使用者交付的題目卷、詳解 | 40.8 MB → 0.88 MB、0.90 MB；逐頁三倍解析度像素相同，文字相同；每份約 2–8 秒 |
| 只合併重複字型 | 40.8 MB → 20.7 MB，約 0.03 秒 |
| 通用字型精簡工具（PyMuPDF 內建、fontTools 依 Unicode） | 內建精簡對此 CFF 字型報錯；依 Unicode 精簡會丟掉數學斜體字母，8 頁中 6 頁畫面改變，已不採用 |
| 印刷文字檢查 | LaTeX 指令、`$x$`、未配對上標、未宣告公式圖、圖檔雜湊不符皆在存題時列出；`US$30,000`、`NT$ 500`、`A \ B`、H₂O 不誤判 |
| 圖寬、末頁 | 460 pt 的圖在有題號欄的選擇題以欄寬印出；只溢出一個題塊的版面以 0.75 倍題間距收回同一頁 |
