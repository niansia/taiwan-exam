# 網頁版固定模板與難度退化修正（2026.09.13.3）

本次以使用者提供的數 A 題本 8 頁、詳解 7 頁查核。未取得網頁端的
run-state、計時紀錄或已安裝 Skill 版本，不能推定該次執行過哪些工具，
也不能斷言是平台超時造成。使用者的 PDF 不納入公開套件。

## 已確認的原因

題本封面與公式頁是重新排出的內容；詳解使用另一套頁首頁尾。
直接比對保存的 PDF，可見其固定區域與原始模板不同，也缺少原始
PDF 內容串流。這不只是主觀字體喜好。使用 XeLaTeX 本身不是錯誤；
它可排新題目的內文，但不能重畫鎖定的封面、頁面固定文字或公式頁。

原有 compositor 在組版當下會比對固定區域，但最後交付檢查只讀取
`template_composition` 的通過紀錄，沒有對最終 PDF 再做一次比對。
因此跳過 compositor 或拿另一份 PDF 交付，未必會被這個紀錄檢查擋下。
本機的舊 official-named HTML wrapper 也能重畫頁首頁尾；文件又把本機
與網頁的正式組版規則分開敘述，留下模糊的替代路徑。

難度方面，網頁 checker 原本只要求記錄難度與平衡審閱，未直接執行
已嵌入的數學設計、四級難度平衡檢查。既有盲審又沒有明確扣除題組中
前題給出的結果；官方 anchor 只需文字敘述，未綁定實際來源頁。
這些是可重現的工具缺口；仍不能據此宣稱已知那次網頁模型的內部流程。

## 題目本身的問題

本次題本可見基本函數性質、直接分類組合與公式代入大量集中。
遞迴只問第六項時，可直接算出前幾項，詳解使用一般解不會增加必要難度。
平面題組的前題已提供法向量，後題求平面式就只需代入一點；不能再把
取得法向量算成後題的獨立決策。最後一題仍有可行域／垂足的實質檢查，
所以也不能把整卷所有題目一概判成簡單。

這是依題幹與最短解法的專家檢視，沒有學生試測，不聲稱實測答對率、
鑑別度或精確作答時間。加新聞背景、拉長詳解、拆開算式行數或提高
作者填寫的難度標籤，都無法修復真正的解法過於直接。

## 修正後行為

- 七科題本與詳解：交付 gate 直接開啟實際檔案，驗證每一份模板的
  大小、SHA-256，以及每頁的固定像素、可達的原始內容串流、奇偶版與
  真實頁數。題本須用該科封面；數 A／B 最後公式內文須保留原始層。
  詳解使用該科內頁固定層，沒有學生封面或公式頁。
- 原始內容串流檢查補足「用圖片仿製外觀」的缺口，固定像素檢查補足
  「藏一份模板卻沒有正確顯示」的缺口。這是排版驗證，不是防惡意竄改
  的身分認證，也不會證明題目內文、字級、碰撞或圖像資訊已審閱。
- 舊 HTML 全頁流程限內部校樣。本機正式 wrapper 改接受量測好的
  body-only PDF，通過內容交接後組合原始模板，加入文件資訊後再驗證。
  不能僅提供 contract 就沿用重畫頁首的正式輸出路徑。
- 網頁交付時直接執行七科的四級難度平衡檢查，以及數 A／B 的題位
  難度設計檢查。七科都需獨立審閱實際內容，並綁定同科官方 anchor
  的實際檔案、頁次與題號；採用獨立評估後的難度分類再平衡整卷。
- 數學最短解法要計入選項與前題提示；直接代入不能標成難題，也不能
  靠拆成三行計算計入三決策配分。保留原有 80–92 分鐘與至少 50 分
  三決策設計目標，加入 routine-only 題目合計至多 25 分的專案門檻。
  這些是本專案的設計政策，不是大考中心官方標準或學生實測保證。
- 缺少執行、真實審閱或最終版本證據時保持 pending，保存可續作材料。
  不能把通過字樣、公式正確、非官方標示或完成得快當作難度／模板合格。

## 驗證與使用範圍

另以實際程式計時找到像素遮罩的耗時：底層 `set_rect` 在 Python 逐樣本填色。
改為整列位元組處理後，同一數 A 內頁、相同 1.5 倍解析度與遮罩，單次量測
由 0.795 秒降至 0.0068 秒，新舊結果逐位元一致。灰階／透明度、邊界與
空遮罩也有等效性測試。這只量測該函式，整卷命題、難度與視覺審閱仍須
另行計時，不能拿這個數字保證整卷能在平台時間上限內完成。

回歸涵蓋七科題本的封面、奇偶內頁、數學公式，以及七科詳解的固定層；
另測重畫頁面、截圖替代、改動頁首、假通過紀錄、缺少難度設計、題組提示
造成的難度下降，及新增文件資訊後的模板保留。這些是工具與版型測試，
不是新命製七份完整考卷，也不是修復後成卷的教育品質驗收。
