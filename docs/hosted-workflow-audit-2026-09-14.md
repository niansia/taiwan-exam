# 網頁出卷耗時與存檔修正

本次針對 ChatGPT、Claude 等有檔案執行功能的對話環境，修正載入、存檔、組版與接續執行流程。平台的單輪限制仍由平台控制；本機工具速度不代表模型能在固定分鐘數內完成原創命題與審閱。

## 原因與證據範圍

使用者提供的執行紀錄顯示：`reference_preflight` 封閉區間 993.7 秒，其中 `prepare_hosted_run.py` 約 6.2 秒；第二輪留下製圖程式與三張圖，卻沒有 `exam.json`。這是使用者回報的工作目錄檢查結果，本次沒有取得該網頁工作階段的完整原始操作日誌，因此不能精確拆分其餘時間。

程式與舊版資料可確認以下缺口：

1. 舊前置封包內嵌大量來源 JSON，與可另外開啟的參考文件重複。工具輸出截斷後，模型容易反覆讀取同一文件。原生 Skill 也曾推薦直接使用約 2.46 MB 的聚合 MD，造成不必要的正文載入。
2. 實際難度欄位與判斷分散在散文、JSON 與驗證程式中。缺少可直接取得同題號目標值與待填欄位的工具，容易變成反查程式與事後重寫。
3. 規則要求分批存檔，但沒有維護中的寫入工具。中斷前若只完成製圖，下一輪就沒有可接續的題目與詳解。
4. 前置檢查原本每次重新組成證明 PDF、重畫檢查圖；常見組版工作也需要逐一串接兩本 PDF 的工具。接續時缺少對不變輸入的可靠重用。
5. 正文公式素材原本未完整支援選項、表格與部分段落；單頁 PDF 素材直接交給 HTML 圖片標籤會產生缺圖。選填欄的表格版面則可能不碰撞卻偏離題幹基線。

## 已實作

- **短版原生入口**：工具 ZIP 保留分開的程式與規則；聚合 MD 僅作專案／知識區相容格式。
- **分段閱讀**：各階段使用索引與順序分段，每段上限 12,000 字元。標明已完整內嵌的 Markdown；JSON 只留檔案、雜湊與精確欄位路徑。
- **命題骨架與欄位契約**：`emit_item_skeleton.py` 直接使用既有官方結構與難度目標函式；另附難度 schema 與 enum／雜湊欄位說明。尚未判斷的欄位維持 null／pending。
- **命題前計畫檢查**：`check_paper_plan.py` 檢查官方計分小題、配分、四級難度計畫、五軸分割、單選位置／多選入選次數、視覺配置與時間。計畫通過不代表題目品質通過。
- **可恢復的小批次存檔**：`append_items.py` 每批保存 1–4 題與詳解，建議 2–4 題。先原子替換 `exam.json` 再更新 checkpoint；中途停止後，重送同批不重複新增。既有內容不同時需明確指定替換；舊審閱不會自動改成通過。
- **重用與一次組版**：前置成果與兩本 PDF 的組版結果綁定實際輸入、工具與產物雜湊。變更輸入必須重建；不變時可直接接續。缺少或過期的 QA 證據仍無法完成。
- **正文排版**：各類文字欄位均支援驗證過的公式素材；只將新製作的單頁正文 PDF 素材轉成可顯示圖片，原始固定模板仍保留 PDF 圖層。選填使用題幹段落內的位置，避免三欄與圈圈偏離文字。數學卷阻擋「第15題圖：」等製作標籤，保留有意義的軸標、單位與圖一／圖二對照。
- **風險提示與視覺審閱**：機械檢查加入 `needs_full_resolution_review`、原因及較高解析度圖片。每一頁與必要題塊仍需真正查看，旗標為 false 不代表已審閱。
