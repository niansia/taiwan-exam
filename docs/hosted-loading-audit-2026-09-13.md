# 網頁載入與逾時調查

## 已知與未知

使用者附上數 A 題本版型、詳解版型及離線模板資源 PDF，並要求依 Skill 原創命題與分冊交付。這是有效的附件組合。畫面顯示流程已經過規格與來源查詢、驗算，最後停在正文排版附近並出現「訊息遞送逾時」。

截圖沒有每階段的開始／結束時間、最終計時檔或平台錯誤紀錄，因此不能把它確診成下載慢、固定 25 分鐘上限或單一工具失敗，也不能由活動標題判定全部動作實際完成。以下是儲存庫與本機測量，並非重播該網頁對話。

## 可重現的載入負擔

2026.09.13.7 的數 A 選科抽取會保留 82 個區段、1,152,414 bytes。其中跨科來源表為 403,782 bytes，SKILL.md 為 78,428 bytes。抽取本身約 0.045 秒；保留這些檔案供程式執行合理，但將它們全部放進模型閱讀內容，或到命題後才反覆查 schema 與工具介面，會增加理解與銜接工作。

這是可確認的流程風險，不代表使用者那輪實際讀完了所有 82 個區段。原版文字雖要求只讀當科，工具卻主要提供完整檔案清單，沒有可直接讀的階段資料。

## 本次修正

- 新增 `read_web_knowledge.py --reading-plan`：一次解出原始工具依賴，另外產生前置、命題、排版、驗收四份閱讀資料。
- 首份資料只呈現跨科來源表與模板表的當科原始紀錄，保留來源雜湊和 JSON 位置；給驗證工具的完整原始表完全不變。
- 命題階段即提供題目、答案、圖像格式及品質要求，排版階段提供既有元件與當科示範，減少寫完才查格式、重寫排版程式的機會。
- 已附離線資源時直接傳入前置工具；瀏覽器加上的 `(1)`、`(8)` 檔名後綴不影響使用。預覽 PDF 只供視覺參考，不能拿占位內容重新組成題庫。
- 將歷屆校準抽查與新素材查證分開；近期事件的必要查證保留。校準、難度、答案及最終逐頁／逐題檢查不因速度要求減少。

閱讀資料只負責安排順序，相關連結與尚未讀取的必要規則仍須依任務讀取。這次沒有縮小整份知識檔，也沒有把「較小的首份閱讀資料」當成整輪耗時的等比例改善。

## 下一次網頁測試

以新版知識檔更新原本的 Skill／Project／Gem，原有三份 PDF 可以繼續使用。代理應先執行階段抽取、使用離線前置，再於前幾題完成試排，保留 QA 時間與可恢復的同卷進度。

若再次中斷，實際 `generation-timing.json`、當輪工具輸出與保存的工作檔才能用來區分「閱讀／推理」「命題驗算」「排版修正」「視覺審閱」的耗時。缺少這些資料時，不能用總對話時間補造各階段紀錄。
